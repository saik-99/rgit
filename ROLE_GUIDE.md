# 🏙️ UrbanIncident Fusion — Team Role Playbook

This playbook defines the exact workflows, folder boundaries, and deliverables for each role working on **UrbanIncident Fusion & Causal Intelligence**.

---

| Role | Domain | Assigned Folder | Primary Deliverables |

## 🧭 Person 1: Frontend & Backend Lead (Full-Stack Engineer)

> **Objective**: Build the live ingestion pipeline and the Operator Incident Command Console that wows the judges.

### 📁 Your Domain: `frontend/` & `backend/`
- `backend/server.py`:
  - `POST /api/events/ingest`: Ingests raw events (IoT, camera, 311, weather).
  - `GET /api/incidents`: Returns evolving clustered incidents with causal graphs.
  - `POST /api/incidents/:id/explain`: Calls Person 4's agent for an operator briefing.
  - WebSocket / SSE for live streaming alerts.
- `frontend/index.html` & `frontend/dashboard.js`:
  - **Operator Map / Grid**: Displays active incidents with severity colors (Red/Yellow/Green).
  - **Causal Graph Visualizer**: Shows the evidence DAG (Root Cause ➔ Symptoms ➔ Alerts).
  - **Confidence & Uncertainty Gauge**: Displays evolving probability (e.g., 65% ➔ 92% as more evidence arrives).
  - **Event Feed**: Live ticker of incoming raw signals with source icons (Camera 📷, IoT 💧, 311 📞).
  - **Operator Briefing Box**: Formatted narrative generated by Person 4's agent.

### 💡 Antigravity Prompting Tip
> *"I am Person 1. Build an Operator Command Console dashboard in `frontend/` that visualizes an evolving incident graph (root cause node pointing to symptom nodes), confidence meter, and incoming signal ticker."*

## 🧠 Person 2 & Person 3: Data, ML & Causal Intelligence Squad

> **Objective**: Person 2 and Person 3 work as a team inside `data_and_ml/` to build the data streams, clustering, causal graphs, benchmarks, and the pitch!

### 📁 Shared Domain: `data_and_ml/`
- `data_and_ml/datasets/`:
  - `incident_vocabulary.json`: Constrained taxonomy of causes and symptoms (e.g. `DrainageFailure` ➔ `WaterLevelSpike`, `TrafficSlowdown`, `CitizenFloodCall`).
  - `synthetic_city_stream.json`: Curated time-stamped city events with out-of-order timestamps, duplicates, and noise.
- `data_and_ml/correlation/spatio_temporal_cluster.py`:
  - Groups raw events within geospatial radius (e.g. 500m) and temporal window (e.g. 20 mins) into candidates.
- `data_and_ml/causal_engine/causal_graph.py`:
  - Builds the directed causal graph and computes probable root cause using prior/evidence likelihoods.
- `data_and_ml/models/severity_model.py`:
  - Calculates Severity (Low/Medium/High/Critical) and Confidence Score (0.0 to 1.0).
- `data_and_ml/research_and_pitch/`:
  - `SCENARIO_BENCHMARKS.md`: The 3 core test scenarios (out-of-order drainage failure, traffic collision with conflicting report, sensor tampering).
  - `PITCH_DECK.md`: Slide-by-slide 3-minute pitch deck for the judges.
  - `DEMO_SCRIPT.md`: Second-by-second live demo workflow.

### 🤝 Division of Labor between Person 2 & Person 3:
- **Person 2 (Focus: Code, ML & Causal Logic)**:
  - Writes the Python clustering logic (`spatio_temporal_cluster.py`).
  - Builds the causal evidence graph (`causal_graph.py`) and severity scoring (`severity_model.py`).
  - Exports clean functions for Person 1: `cluster_events(events)` and `build_causal_graph(cluster)`.
- **Person 3 (Focus: Data Design, Benchmarks & Pitch)**:
  - Designs realistic multimodal events in `synthetic_city_stream.json` (timestamps, coordinates, source types).
  - Writes the out-of-order replay benchmark scenarios in `SCENARIO_BENCHMARKS.md`.
  - Crafts the 3-minute winning Pitch Deck and scripts the live demo in `PITCH_DECK.md` and `DEMO_SCRIPT.md`.

### 💡 Antigravity Prompting Tip
> *"We are Person 2 & 3 working in `data_and_ml/`. Implement a Python causal graph builder in `data_and_ml/causal_engine/causal_graph.py` that ingests clustered events and outputs a root cause with confidence score."*

## 🤖 Person 4: AI Agent Manager & Explainability Specialist

> **Objective**: Build the intelligence agent that inspects the evolving incident graph, resolves conflicts, and gives clear operational briefings to human dispatchers.

### 📁 Your Domain: `agents/`
- `agents/prompts/operator_prompts.md`: System prompts and few-shot examples for causal reasoning and operational briefings.
- `agents/tools/graph_tools.py`: Helper tools to inspect graph nodes, calculate edge weights, and flag source discrepancies.
- `agents/incident_agent.py`:
  - Main function: `analyze_incident(incident_graph: dict) -> dict`
  - Detects conflicting evidence (e.g., citizen says "fire" while sensor shows "cold water").
  - Evaluates cybersecurity device integrity flags.
  - Generates confidence-aware operator briefings (e.g., *"Confidence is 68% due to missing sensor feed; dispatching drone recommended to confirm."*).

### 💡 Antigravity Prompting Tip
> *"I am Person 4 (Agent Specialist). In `agents/incident_agent.py`, create an agent that takes an incident graph, resolves out-of-order conflicting signals, and outputs an operator summary with recommended actions."*

## 🚀 Collaborative Git Flow

```bash
# Person 1:
git checkout -b feature/command-center

# Person 2 & 3:
git checkout -b feature/data-and-causal-ml

# Person 4:
git checkout -b feature/incident-agent
```

### Pull Requests & Merging:
1. Person 2 & 3 push their PR touching only `data_and_ml/`.
2. Person 4 pushes their PR touching only `agents/`.
3. Person 1 merges both into `main` and imports the functions into `backend/server.py` and `frontend/`.
